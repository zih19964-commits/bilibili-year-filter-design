# 发布前初始化

发布前先准备一个可复现的本地工作区，并确认发布内容来自正确的 Git 分支。

## 1. 获取仓库

已有本地仓库时直接进入项目目录。其他机器可以执行：

    git clone <GitHub 仓库地址>
    cd bilibili-year-filter-design

本项目没有运行时依赖，通常不需要执行 npm install。本地 Node.js 可用后，直接运行检查命令即可。

## 2. 检查工作区

    git status --short --branch
    git remote -v
    git log -1 --oneline

确认当前分支和远程地址正确。发布前必须审阅所有未提交文件；不要把本地调试日志、个人配置或尚未验证的实验代码带入发布提交。

## 3. 检查许可证和发布入口

确认以下内容存在并且相互一致：

- 根目录 LICENSE 为 MIT License；
- package.json 中的 license 为 MIT；
- [使用说明](../使用说明.md) 能够指导用户安装 Userscript 和扩展；
- starter/tampermonkey/bilibili-year-filter.user.js 可以直接安装；
- starter/extension/manifest.json 引用的文件都存在。

MIT 许可证只覆盖项目作者或贡献者拥有相应权利的原创内容。Bilibili 商标、网页内容、接口数据、截图和其他第三方材料需要分别确认权利边界。

## 4. 选择版本

发布标签、用户脚本元数据、扩展 manifest.json 和 package.json 的版本应当统一。目前仓库中的版本字段仍需在正式发布前确认是否统一：用户脚本和 package.json 为 1.0.0，扩展 manifest 为 0.1.0。版本未对齐前不要直接创建正式 Release。

## 5. 验证环境

在发布提交前执行：

    npm test
    npm run check
    git diff --check

预期结果是测试全部通过、语法检查显示 syntax ok，并且 git diff --check 没有错误。
