# 发布提交

发布提交应当是一个经过检查、可被版本标签准确指向的干净提交。提交前先查看变更范围：

    git status --short
    git diff --stat
    git diff --check

确认变更内容后，只暂存本次发布需要的文件：

    git add <已审阅的文件>
    git diff --cached --stat
    git diff --cached --check

工作区存在其他未完成修改时，不要直接执行 git add .，避免把无关修改、调试文件或未验收代码放进发布提交。当前项目包含 Userscript、扩展、文档和测试，提交前应特别检查这些目录是否混入临时文件。

验证通过后提交：

    git commit -m "release: prepare <版本号>"
    git log -1 --oneline

提交后再次确认提交内容：

    git show --stat --oneline HEAD
    git status --short --branch

只有确认 HEAD 指向预期提交、工作区剩余修改均已知晓后，才进入 [发布](发布.md) 流程。推送远程仓库前应确认远程地址属于自己的 GitHub 仓库。
